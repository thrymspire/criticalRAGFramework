# Critical Path RAG Architecture: Multi-Distro Topology & Data Flow
**Document Classification:** Core Architecture Specification  
**Cluster Architecture:** Decoupled 3-Tier Multi-Distro Pipeline  
**Target Environment:** Windows 11 Enterprise + WSL2 Virtualization (Linux Kernel 6.18+ / Ubuntu 26.04 LTS)

---

## 1. Architectural Philosophy: The Three Invariants

The Critical RAG design enforces three non-negotiable operational invariants:

```
+-----------------------------------------------------------------------------------------------+
|                                     WINDOWS 11 HOST SYSTEM                                    |
|   Resource Management: .wslconfig (16GB RAM limit, 12 cores, autoMemoryReclaim=gradual)      |
+-----------------------------------------------------------------------------------------------+
       |                                      |                                      |
       v                                      v                                      v
+-------------------------------+  +-------------------------------+  +-------------------------------+
| DISTRO 1: STATE ANCHOR        |  | DISTRO 2: INFERENCE & DAG     |  | DISTRO 3: EVALUATION GATE     |
| criticalpath-store-v1.0       |  | criticalpath-pipeline-v1.0    |  | criticalpath-eval-v1.0        |
| - Persistent DB & Vector Store|  | - Stateless Transformation    |  | - Ephemeral (On-Demand)       |
| - PostgreSQL 18 + pgvector    |  | - Snakemake Hierarchical DAG  |  | - Ragas / TruLens Framework   |
| - FastMCP Daemon Bridge       |  | - LangChain / LangGraph Node  |  | - Synthetic Test Split Engine |
| - WAL Tuned for Local NVMe    |  | - Local Ollama / DirectML     |  | - Precision/Recall/Faithful   |
| - Zero LLM Weights / Agents   |  | - Direct Silicon (/dev/dxg)   |  | - Shuts Down Post-Run         |
| 127.0.0.1:5432 / :8000        |  | 127.0.0.1:11434 / :8080       |  | Client Loopback Query Only    |
+-------------------------------+  +-------------------------------+  +-------------------------------+
       ^                                      ^                                      ^
       |====== Loopback (127.0.0.1) IPC ======|======================================|
       |                                      |
       +----- Shared Mount: /mnt/wsl/rag-store-data -----+
```

1. **State Isolation (The State Anchor):**  
   The database distro never executes AI agent logic, never compiles embeddings, and never hosts LLM model weights. It does one thing with maximum reliability: fast indexed similarity queries and ACID metadata transactions.
2. **Compute Isolation (The Transform Node):**  
   The compute distro has direct GPU hardware pass-through (`/dev/dxg`) for local embedding generation and inference. It is completely stateless; if it crashes under OOM spikes during heavy document chunking, zero database state or indexes are corrupted.
3. **Verification Isolation (The Verification Gate):**  
   Evaluation runs require high compute and generate metric artifacts that pollute production databases if co-located. The eval gate is started on-demand via batch automation, issues test queries across localhost, logs regression metrics, and immediately terminates to return RAM to the OS.

## 2. Inter-Distro Networking & IPC

In WSL2, all running distros share the host virtual network interface card and resolve each other seamlessly over the host loopback adapter:
- **Port 5432:** PostgreSQL wire protocol listening on `127.0.0.1:5432`. Accessible directly by the pipeline distro using `psycopg`, `asyncpg`, or `SQLAlchemy`.
- **Port 8000:** FastMCP Protocol Bridge daemon listening on `127.0.0.1:8000`. Exposes MCP tools (`search_chunks`, `fetch_document_context`, `filter_metadata`) to Claude Desktop, Antigravity, or LangGraph.
- **Port 11434:** Ollama / Local inference HTTP API listening on `127.0.0.1:11434`.

---

## 3. Shared Storage Layer (`/mnt/wsl/`)

WSL2 provides a lightning-fast in-memory tmpfs / cross-distro mount located at `/mnt/wsl/`:
- **Mount Path:** `/mnt/wsl/rag-store-data`
- **Subdirectories:**
  - `raw_documents/`: Unprocessed incoming PDF, Markdown, JSON, and DOCX files.
  - `hierarchical_chunks/`: Intermediate parquet/JSON chunk trees generated by the Snakemake DAG.
  - `embeddings_cache/`: Memory-mapped cache for vector calculations to prevent redundant API/GPU calls.
  - `wal_archive/`: PostgreSQL write-ahead log backups for disaster recovery.

---

## 4. Hardware Acceleration & Direct Silicon Access

The Transform Node (`criticalpath-pipeline-v1.0`) binds directly to the host DirectX kernel driver via `/dev/dxg`. This enables:
- Direct3D 12 and Vulkan compute without requiring bare-metal Linux Nvidia/AMD driver installations.
- DirectML and ONNX Runtime execution for sub-second text embedding generation (e.g. `nomic-embed-text`, `bge-m3`).
- Ollama / llama.cpp GPU offloading directly from WSL2 into the host GPU VRAM.
